# Plan: Fix Driver Profile Linking UX

## Root Cause Analysis

The empty driver dropdown bug in `/users` Profile Links tab is caused by **silent error swallowing** in `UserDetailPage.tsx` line 122:
```tsx
try { const dRes = await getDrivers(...); setAllDrivers(dRes.data?.items ?? dRes.data ?? []); } catch {}
```
If the API call fails (403, timeout, network error), `allDrivers` stays `[]` with no visible error. The "No available drivers found" text at line 500 only shows when non-inactive drivers are 0, which is the same state as a failed load.

The same pattern exists in `UsersPage.tsx` line 96.

### Task 6 -- Backend Available Drivers Endpoint

**New endpoint**: `GET /api/v1/user-profile-links/available-drivers?search=&showAll=false`

Add to `user-profile-links.routes.ts`:
```ts
router.get('/available-drivers', requirePermission('profile_link_view'), asyncHandler(listAvailableDriversController));
```

Controller queries:
- All drivers (with optional search on name/mobile/licenseNumber)
- For each driver, check if there's an ACTIVE UserProfileLink
- Return: `{ items: [{ driverId, name, mobile, licenseNumber, status, linkedUserId, linkedUsername, isLinked }] }`

Service function `listAvailableDrivers`:
- Query drivers with optional search
- Query active profile links for those driver IDs
- Merge and return

This replaces the separate `getDrivers` + manual cross-referencing on the frontend.
