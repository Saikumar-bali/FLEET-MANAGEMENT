# Plan: Link Drivers to User Accounts + Driver Portal

## Problem
- 9 drivers exist in the `drivers` table, but only 1 has a linked user account
- The other 8 drivers cannot log in
- No driver-specific UI exists after login

## Approach
Auto-create a linked user account when creating a driver, and build a "My Trips" page for drivers.

---

## Part 1: Backend — Auto-Create User When Creating a Driver

### 1.1 Modify driver creation to optionally create a linked user account

**File: `backend/src/modules/drivers/drivers.validators.ts`**
- Add optional fields to `createDriverSchema`:
  - `createAccount: z.boolean().optional()` — whether to create a user account
  - `password: z.string().min(8).optional()` — password for the new account

**File: `backend/src/modules/drivers/drivers.service.ts`**
- In `createDriver()`: after creating the driver, if `createAccount` is true:
  1. Find the "Driver" role by key (`driver`)
  2. Generate a username from mobile or `driver_<mobile>`
  3. Generate email as `<mobile>@driver.fleet.local` (or allow override)
  4. Create a `User` record with `userDriverId` set to the new driver's ID
  5. Return the driver with the linked user info

**File: `backend/src/modules/drivers/drivers.controller.ts`**
- Pass `createAccount` and `password` through to the service

### 1.2 Add a "Link User to Driver" endpoint

**File: `backend/src/modules/drivers/drivers.validators.ts`**
- Add `linkUserSchema`: `{ userId: z.string() }`

**File: `backend/src/modules/drivers/drivers.routes.ts`**
- Add `PATCH /api/v1/drivers/:id/link-user` — sets `User.userDriverId` to the driver's ID

**File: `backend/src/modules/drivers/drivers.service.ts`**
- Add `linkUserToDriver(driverId, userId)`:
  1. Verify driver exists
  2. Verify user exists and doesn't already have a linked driver
  3. Update `User.userDriverId = driverId`

### 1.3 Include linked user info in driver list/detail responses

**File: `backend/src/modules/drivers/drivers.service.ts`**
- In `listDrivers()` and `getDriverById()`: add `include: { linkedUsers: { select: { id, name, email, username, status } } }`
- This lets the frontend show which drivers have accounts

### 1.4 Add driver-scoped trips endpoint

**File: `backend/src/modules/trips/trips.routes.ts`** (or reuse existing)
- The existing `GET /api/v1/trips?driverId=<id>` already supports this
- No new endpoint needed — just ensure the frontend uses it

**File: `web/src/pages/DriverDetailPage.tsx`**

## Part 3: Driver Portal — "My Trips" Page

### 3.1 Backend: Get current driver's trips

**File: `backend/src/modules/trips/trips.routes.ts`**
- The auth middleware already resolves `req.authUser` from the JWT
- When a driver-role user is logged in, their `userDriverId` links to a Driver record
- Add logic: if the requesting user has role "driver", auto-filter trips by their linked driver ID (or allow the frontend to pass it)

**File: `backend/src/modules/auth/auth.service.ts`**
- In `mapUserWithPermissions()`: include `userDriverId` in the returned user object so the frontend knows which driver record is linked

**File: `backend/src/types/auth.ts`**
- Add `userDriverId` to `RequestUser` type

### 3.2 Frontend: "My Trips" navigation item

**File: `web/src/config/navigation.ts`**
- Add a new navigation item for drivers:
  ```
  { label: 'My Trips', path: '/my-trips', permissionKeys: ['trip_view'], section: 'EXPLORE' }
  ```
- This only shows for users with the driver role

### 3.3 Frontend: My Trips page

**File: `web/src/pages/MyTripsPage.tsx`** (new file)
- A simplified trips list filtered to the current driver's trips
- Shows: Trip #, Vehicle, Route, Status, Start/End times
- Click a trip to see detail (reuse `TripDetailPage`)

**File: `web/src/App.tsx`** (or router config)
- Add route `/my-trips` -> `MyTripsPage`

**File: `web/src/services/api.ts`**
- Add `getMyTrips(token)` that calls `GET /api/v1/trips?driverId=<currentDriverId>`
  - The `currentDriverId` comes from the auth context (via `userDriverId` on the logged-in user)
