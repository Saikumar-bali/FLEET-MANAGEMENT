## Final Validation Hardening
- **Create document status restricted to DRAFT/ACTIVE only** — VERIFIED, REJECTED, EXPIRED, RENEWAL_DUE cannot be set on create
- **Update document status restricted to DRAFT/ACTIVE only** — VERIFIED, REJECTED, EXPIRED, RENEWAL_DUE cannot be set via normal update (requires `document_metadata_update` permission)
- **Verify workflow cannot be bypassed** — VERIFIED/REJECTED require the dedicated verify endpoint (`document_metadata_verify` permission)
- **Renew endpoint sets ACTIVE** — renewing a document automatically sets status to ACTIVE
- **Expired/Renewal_Due** — will be system/computed later, not manually creatable or editable through create/update endpoints

## CI Fix History
1. **Original CI failure** (run 28006613764): `test:vehicle-compliance` failed with `Cannot read properties of undefined (reading 'some')`

3. **Fix**: Added `asItems()` helper to normalize both array and object responses
4. **Fix**: Added `status` param to `createComplianceDocument` service and Zod schema so ACTIVE docs appear in alerts
5. **Fix**: Test docs created with `status: 'ACTIVE'` instead of defaulting to DRAFT
